# 开放场景视觉语义认知答辩 Demo 设计规范

## 1 文档目的

本文档定义“基于多模态大模型的开放场景视觉语义理解一体机”答辩 Demo 的建设范围、系统架构、功能边界、技术方案、测试方式和验收标准。后续 AI 开发、人工检查、每日工作记录和答辩材料均应以本文档为依据。

> 2026-09-26 范围补充：当前交付只包含可运行 Demo、测试/验收证据和详细用户使用说明。PPT、讲解词、汇报文档和演练不属于当前交付范围；本文档其余“答辩”表述仅作为原始项目背景保留。

本 Demo 用于验证项目书中的核心技术链路，不等同于完整一体机产品，也不承担项目书所列全部性能指标、工程指标和产业化目标。

## 2 建设条件

- 开发周期：14 天。
- 每日投入：3 小时。
- 总工作量：约 42 小时。
- 开发设备：仅 CPU 的个人笔记本电脑。
- 大模型条件：可调用 DeepSeek API，不能在本地部署大模型。
- 小模型条件：可在本地运行轻量视觉模型。
- 视频输入：本期只支持本地视频文件。
- 模型与素材：允许使用公开预训练模型和公开视频。
- 原项目书：只作为需求依据，不修改原文件。

## 3 Demo 目标

Demo 的核心不是完成某一个固定场景，而是验证一个可配置、可扩展的视觉分析平台。平台根据用户的自然语言需求选择合适的场景插件、小模型和规则，并以统一格式输出分析结果。

本期使用两个差异明显的场景证明通用性：

1. 边防场景：使用通用人员车辆检测模型，完成禁区进入、离开和区域滞留判断。
2. 火灾场景：使用火焰烟雾专用检测模型，通过连续多帧确认生成火灾告警。

平台通用性体现在以下方面：

- 模型可注册：新增模型不修改分析主流程。
- 场景可配置：不同场景通过配置和插件切换。
- 规则可组合：区域、停留、数量、连续帧等规则可复用。
- 输出统一：不同模型产生统一的检测结果、事件记录和可视化结果。

## 4 非目标

本期明确不实现以下功能：

- 摄像头实时输入和 RTSP 视频流。
- 两路及以上视频并发分析。
- 本地视觉语言大模型部署。
- 任意开放目标的零样本稳定识别。
- 模型训练和数据标注平台。
- 多摄像头目标关联。
- 人员身份识别。
- 完整自主 Agent Loop。
- 生产级数据库、权限、用户和审计系统。
- 火势等级计算、蔓延预测和消防设备联动。
- 项目书中正式精度指标的完整验证。

## 5 总体架构

系统采用“统一平台加场景插件加多个小模型”的架构。

```text
用户自然语言或预设模板
          |
DeepSeek 场景解析
          |
生成并校验 SceneSpec JSON
          |
场景路由器与模型注册表
      |                  |
   边防插件            火灾插件
      |                  |
通用 YOLO 小模型      火焰烟雾小模型
      |                  |
区域与时序规则        连续帧确认规则
          |
统一事件管理与结果输出
          |
检测框 告警 日志 统计 结果视频
```

DeepSeek 不直接处理视频帧。DeepSeek 只负责理解用户需求、选择场景、选择已注册模型、生成受限规则配置以及解释结果。视频推理由本地小模型完成。

## 6 核心数据流

完整数据流如下：

1. 用户上传本地视频文件。
2. 系统读取视频分辨率、帧率、帧数和时长。
3. 用户输入自然语言需求，或选择预设场景模板。
4. DeepSeek 将需求转换为 SceneSpec JSON。
5. Pydantic 校验场景、模型、目标、规则和参数。
6. 模型注册表加载对应小模型。
7. 视频模块逐帧读取并根据 CPU 性能执行抽帧。
8. 小模型输出统一 Detection 对象。
9. 跟踪模块为目标分配短期 Track ID。
10. 规则引擎根据区域、轨迹、时间和连续帧状态判断事件。
11. 事件管理器执行去重、冷却、截图和记录。
12. 可视化模块绘制检测框、禁区、状态和告警。
13. 系统保存结果视频、JSON、CSV、截图和运行摘要。

## 7 SceneSpec 设计

SceneSpec 是自然语言配置与本地视觉执行之间的受限接口。建议结构如下：

```json
{
  "scene_type": "border",
  "model_id": "yolo_general",
  "targets": ["person"],
  "rules": [
    {
      "type": "enter_region",
      "params": {
        "region_id": "restricted_zone",
        "polygon": [[120, 80], [520, 80], [520, 400], [120, 400]]
      }
    }
  ],
  "alert": {
    "enabled": true,
    "cooldown_seconds": 5
  }
}
```

校验要求：

- `scene_type` 必须来自场景白名单。
- `model_id` 必须已经注册。
- `targets` 必须被所选模型支持。
- `rule.type` 必须来自规则白名单。
- 所有时间、数量、帧数和置信度阈值必须在预设安全范围内。
- DeepSeek 输出不得包含 Python、Shell、文件路径或任意可执行命令。
- 校验失败时不得执行，系统转入人工模板配置。

## 8 模型插件设计

### 8.1 统一模型接口

所有小模型必须实现统一适配器接口：

```python
class ModelAdapter:
    def load(self) -> None:
        ...

    def predict(self, frame) -> list[Detection]:
        ...

    def unload(self) -> None:
        ...
```

统一检测输出至少包含：

- 帧编号。
- 类别名称。
- 置信度。
- 边界框坐标。
- 可选 Track ID。

业务规则不得直接依赖某个 YOLO 版本的原始返回对象。

### 8.2 边防插件

边防插件使用轻量通用 YOLO 模型，主要支持人员和常见车辆类别。

功能包括：

- 人员、汽车、卡车和摩托车检测。
- 类别过滤和置信度过滤。
- 目标短期跟踪。
- 禁区多边形绘制和进入/离开判断。
- 区域内停留时间计算。
- 同一目标的告警冷却和去重。

边防插件不提供人员身份识别、远距离小目标增强、军事目标识别和多摄像头关联。

### 8.3 火灾插件

火灾插件使用公开火焰烟雾检测权重。

功能包括：

- 火焰检测。
- 烟雾检测；若候选模型验证不稳定，可将本期范围缩小为火焰检测。
- 火焰和烟雾独立置信度阈值。
- 连续多帧确认。
- 短暂漏检容错。
- “疑似”和“确认”两级状态。
- 首次发现时间和确认时间记录。
- 同一事件的告警冷却和去重。

## 9 通用规则引擎

第一版规则引擎支持：

- `object_present`：指定目标出现。
- `enter_region`：目标进入区域。
- `leave_region`：目标离开区域。
- `dwell`：目标停留超过阈值。
- `count_greater_than`：目标数量超过阈值。
- `consecutive_frames`：连续若干帧满足条件。
- `confidence_greater_than`：置信度超过阈值。
- `and`：多个条件同时满足。
- `or`：任一条件满足。

本 Demo 实现目标、区域、行为、时间和触发五类语义要素。复杂属性识别作为后续扩展。

## 10 视频处理

视频模块支持：

- 上传 MP4、AVI、MOV 视频。
- 校验格式、大小、时长和首帧可读性。
- 读取分辨率、帧率、帧数和时长。
- 开始、停止和重新分析。
- CPU 模式下自动抽帧。
- 写出带标注的结果视频。
- 任务停止或异常时释放视频句柄。
- 为后续摄像头和 RTSP 输入预留统一接口。

CPU 优化策略：

- 优先使用 nano 级模型。
- 默认输入尺寸为 640；性能不足时依次降为 512 或 416。
- 检测帧之间可使用跟踪状态补充。
- 答辩视频建议控制在 15 至 30 秒。
- 页面显示进度和抽样预览，完成后播放结果视频，不要求达到原始视频实时帧率。

## 11 事件管理与结果输出

每条事件至少包含：

- 事件 ID。
- 场景类型。
- 事件类型。
- 目标类别。
- Track ID。
- 视频时间点。
- 置信度。
- 触发规则。
- 截图路径。
- 告警状态。
- 模型名称。

每次运行生成独立目录：

```text
runs/<run_id>/
├── config.json
├── events.json
├── events.csv
├── summary.json
├── result.mp4
└── snapshots/
```

统一输出必须支持结果回放、事件筛选、告警截图查看以及 JSON、CSV 和结果视频下载。

## 12 Web 页面

系统使用单页 Streamlit 界面，避免答辩时频繁切换页面。

页面布局：

1. 顶部显示项目名称和系统状态。
2. 左侧提供视频上传、自然语言输入、模板选择和参数设置。
3. 中部显示视频预览和处理结果。
4. 右侧显示 SceneSpec、当前模型和任务状态。
5. 下部显示告警记录、统计结果和文件下载。
6. 高级参数默认折叠。

页面主要功能：

- 边防、火灾和自然语言自动选择三种模式。
- DeepSeek 配置结果确认和人工修改。
- 当前模型、处理进度和性能状态显示。
- 结果视频播放。
- 告警表格和截图查看。
- JSON、CSV 和结果视频下载。

## 13 预设场景模板

系统至少提供四个离线模板：

1. 边防人员禁区：人员进入多边形区域。
2. 边防车辆禁区：车辆进入多边形区域。
3. 边防滞留：人员进入区域并停留超过阈值。
4. 火灾检测：火焰或烟雾连续出现若干帧。

模板用于 DeepSeek 不可用时继续演示，也用于对比自然语言配置和人工配置结果。

## 14 错误处理与降级

- API Key 缺失：进入模板模式。
- DeepSeek 超时：自动重试一次，仍失败则进入模板模式。
- DeepSeek JSON 无效：重新请求一次，仍失败则要求人工选择模板。
- 模型权重缺失：禁止启动任务并显示缺失文件。
- 模型类别与目标不兼容：阻止执行。
- 视频损坏：在推理前返回明确错误。
- 视频编码失败：保留已生成的 JSON、CSV 和截图。
- 用户中途停止：释放资源并保存已有事件。
- 单条规则异常：记录错误并跳过，不使整个视频任务崩溃。
- CPU 过慢：降低输入尺寸并增加抽帧间隔。
- 火灾模型误报：提高置信度阈值并增加连续帧要求。
- 答辩断网：使用离线模板、已缓存权重和本地样例视频完成演示。

## 15 测试设计

### 15.1 单元测试

- SceneSpec 合法配置通过校验。
- 非法场景、模型和规则被拒绝。
- 目标进入多边形区域触发进入事件。
- 目标离开多边形区域触发离开事件。
- 停留时间未达到阈值时不报警。
- 连续火焰帧不足时不报警。
- 告警冷却期间不重复记录。
- 同一 Track ID 不重复产生同类事件。

### 15.2 集成测试

- 边防样例视频生成结果视频和事件文件。
- 火灾样例视频生成结果视频和事件文件。
- DeepSeek 断网时模板模式可继续运行。
- CPU 环境连续处理两个视频后资源正确释放。
- JSON、CSV、截图和运行摘要数据一致。

### 15.3 答辩验收

- 两类模型能够自动切换。
- 边防和火灾视频都能完成处理。
- 至少触发一个边防事件和一个火灾事件。
- 自然语言能够转换为可读、可修改、可校验的 SceneSpec。
- 模型切换不修改代码。
- 告警包含截图和视频时间。
- 断网后模板模式仍可演示。
- 全流程能够在 5 分钟内展示完毕。

各模块必须保持清晰边界：

- `pipeline` 负责串联模块，不包含具体模型和规则实现。

## 19 主要风险与控制措施

### 19.1 火灾模型效果不稳定

- 第 3 天完成模型筛选，不将风险拖到后期。
- 保留主模型和备用模型。
- 固定经过验证的演示视频。
- 通过连续帧确认降低单帧误报。
- 烟雾效果不稳定时，将本期范围缩小为火焰检测。

### 19.2 CPU 推理速度不足

- 使用 nano 级模型。
- 降低输入尺寸。
- 增加抽帧间隔。
- 将演示视频限制在 15 至 30 秒。
- 预先生成备用结果视频。

### 19.3 DeepSeek 网络异常

- 保存四个离线模板。
- 允许人工编辑 SceneSpec。
- 确保视觉处理主流程不依赖 DeepSeek 才能运行。

### 19.4 公开素材与规则不匹配

- 第 2 天和第 3 天固定最终视频。
- 根据视频内容设置禁区和阈值。
- 答辩当天不临时更换素材。

### 19.5 界面开发超时

- 只做单页 Streamlit。
- 不做登录、数据库、用户管理和复杂图表。
- 第 12 天后冻结页面结构。

## 20 答辩展示流程

建议总时长为 5 分钟：

1. 说明项目痛点和 Demo 目标。
2. 展示统一平台、场景插件和模型注册架构。
3. 上传边防视频并输入自然语言需求。
4. 展示 SceneSpec 和自动选择的边防模型。
5. 播放边防结果并展示禁区进入、离开或滞留告警。
6. 切换火灾视频并输入火灾需求。
7. 展示火灾模型和连续帧确认告警。
8. 对比两个场景使用不同模型，但共享配置、规则和输出机制。
9. 展示事件截图、JSON、CSV 和结果视频。
10. 说明当前 Demo 边界和后续产品化方向。

## 21 最终完成标准

Demo 完成必须同时满足：

- 边防和火灾两个真实模型插件可运行。
- 本地视频文件可上传和处理。
- DeepSeek 可将自然语言转换为 SceneSpec。
- 模型可根据场景自动选择。
- 边防至少实现一种空间或时序事件。
- 火灾实现连续帧确认。
- 不同模型输出统一 Detection 和 Event。
- 页面可显示检测框、规则区域、事件和统计信息。
- 系统可输出结果视频、JSON、CSV 和截图。
- DeepSeek 不可用时模板模式可运行。
- 核心规则具备自动化测试。
- 答辩讲解、操作清单和离线备用结果齐全。

## 22 后续扩展方向

在答辩 Demo 验证完成后，可按以下顺序扩展：

1. 接入摄像头和 RTSP 视频流。
2. 支持两路及以上视频并发。
3. 增加安全帽、反光衣、人员聚集等场景插件。
4. 增加更完整的属性识别与空间关系规则。
5. 引入视觉语言模型 API 或本地算力设备，增强开放目标理解。
6. 建设场景模板库、模型资源库和测试数据集。
7. 实现证据补帧、时间窗口调整和局部复核等闭环能力。
8. 开展正式精度、召回率、误报率和响应时延测试。
9. 迁移至一体机硬件并开展现场 POC。
