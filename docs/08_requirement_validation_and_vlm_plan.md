# DeepSeek 需求校验与多模态检验建议

日期：2026-09-27。需求校验和 Qwen 多模态检验现均已实现，并通过真实转头视频的正反例测试。下文保留设计依据，最终操作、实现限制与验收见 [Qwen 视频检验](09_qwen_video_inspection.md)。

## 当前网页行为

需求应包含可从视频观察到的对象及要检测的行为或状态。不限于严格的一个语法句子，也不强制包含“报警”；同一段话可以包含多个条件，但必须全部可执行。

| 输入示例 | 结果 | 页面行为 |
| --- | --- | --- |
| 你好、请讲一个笑话 | 非场景需求 | 提示填写监测对象与行为，不生成配置 |
| 帮我看看视频有没有异常 | 需求不明确 | 要求说明具体异常，不猜测检测任务 |
| 检测人员未戴安全帽并报警 | 有效需求，但现有能力不支持 | 列出缺失能力，停止生成本地配置 |
| 监测人员进入禁区，并检查是否佩戴安全帽 | 部分能力不支持 | 整体停止，不删除安全帽条件后继续执行 |
| 连续监测到火焰8秒后报警 | 可执行 | 上传视频后按实际帧率换算；25 FPS 为201个连续命中帧 |
| 岗位连续无人5秒后报警 | 可执行 | 生成人员在岗规则，需要核对并绘制岗位区域 |
| 单人近景视频中双眼持续闭合2秒后提示 | 可执行 | 生成持续闭眼规则；这是疑似打瞌睡提示，不证明已睡眠 |

明显空白、纯符号、问候等在本地拒绝，不消耗 API 调用；其他语句由 DeepSeek 做语义判断。DeepSeek 只接收文字和可选的视频宽高、帧率，无法判断视频中眼睛是否清楚、镜头位置是否合适。

结构化结果包含 `status`、`reason`、`summary`、`requirements`、`unmet_requirements` 和 `scene`。只有 `supported` 才允许继续；本地还要校验模型及类别白名单、规则类型、参数范围、区域坐标，以及原文片段与规则的对应关系。格式错误最多修复一次，语义拒绝直接返回原因。网页不会自动切换到离线模板，也不会把不支持的需求偷偷改成相近任务。

配置卡片上显示“需求理解（请核对）”。更改输入或解析不通过会清除旧配置。缺少数值阈值时可采用提示词中定义的默认值，并应在摘要中说明；未画区域时先生成可编辑默认区域，使用前必须调整。

这些措施减少误执行，但不能数学上保证任意自然语言都理解正确。规则映射校验只能验证结构一致性，无法证明大模型没有漏读一句话。因此摘要核对与后续真实视频验收仍然必要。

实现位置：`src/llm/requirement_guard.py`、`src/llm/scene_parser.py`、`src/llm/prompts.py`、`src/ui/app_service.py`、`app.py`。测试在 `tests/test_requirement_guard.py`。本次193项自动测试通过，以上7条真实接口语义案例通过（对应记录在本机忽略目录 `runs/requirement-live-verification.json`）。

## 多模态检验的建议路线

保留现有小模型作为默认执行方式；对有效但不支持的视觉需求，进入独立的多模态检验流程。不能把“本地不支持”直接等同于“大模型可以完成”：画面不可见的状态、心理意图、无法辨认的小物体，以及发短信等业务动作，都需要分别解释或使用其他模块。

推荐先通过云端 API 接入阿里云百炼的千问视觉模型（Qwen-VL 系列），减少笔记本上的显存和部署要求。其官方接口提供图片、视频理解能力；选定模型后再核对所在地域、端点、输入格式及限制。[官方视觉理解文档](https://help.aliyun.com/zh/model-studio/vision)。Gemini 视频理解可作为另一方案，需要另行测试网络和账号可用性；其文档说明默认视频采样为1 FPS，也支持调整采样率。[官方视频理解文档](https://ai.google.dev/gemini-api/docs/video-understanding)。模型选择仍需使用本项目样例对比，不能仅凭产品介绍认定检测准确率。

建议第一版流程：

1. DeepSeek 将需求整理为清晰、可观察的判定条件，并说明本地缺失能力；页面展示将检验什么。
2. 用户选择多模态检验后，程序分段处理上传视频。明确标示哪些画面会发送到云端，单独配置视觉模型服务，现有 DeepSeek 文字配置接口保持原职责。
3. 每段提取带时间戳的帧，或按提供商支持方式发送短视频；保存帧 ID 到原视频时刻的映射。
4. 大模型返回满足、不满足或无法判断三种结果，并附证据帧 ID 和简短依据。程序验证证据确实来自本次输入，时间范围必须落在对应视频片段内。
5. 对疑似事件使用更密集的帧或原始短片复核，去重后生成疑似事件、截图和时间线；不确定结果保留为待确认。

可先用5–10秒窗口、1–2秒重叠、每秒1–2帧做粗筛，发现疑似事件后以更密集采样或短片复核。这些是待测试的工程起点，不是供应商要求。快速动作容易在粗采样中遗漏；“连续8秒”“始终闭眼”不能只凭稀疏截图证明。未检出时应写“采样范围内未发现”，不能宣称整段视频绝无事件。可连续计时的既有任务继续交给本地逐帧规则。

输出建议包含：`status`、`evidence_frame_ids`、`reason`、`limitations`。事件的起止时间由程序结合证据映射生成；若模型另给时间区间，应验证并标记为估计。没有可靠定位能力时只显示证据截图，不编造目标框；不要把大模型自述的置信度当作校准后的概率。

公网版本应先提供有明确次数上限的手动检验，设置单视频时长、帧数、总请求数和并发上限，再考虑自动转入流程。缓存键包含视频摘要、需求、模型版本和采样设置，以避免重复付费。超时或配额不足显示明确失败状态，不转为“未发生事件”。

建议先验收“安全帽佩戴”“接打电话”等对象与动作清晰的样例，再逐步扩展。对每类任务准备阳性、阴性、遮挡和低画质片段，统计漏报、误报、无法判断比例、耗时及成本。多模态结果先作为疑似事件供查看，取得可接受的数据后再决定是否用于自动报警。

## 已实现的代码接入位置

`src/llm/qwen_client.py` 管理官方服务调用与持久化设置，`src/pipeline/qwen_pipeline.py` 负责抽帧、复核、证据校验、标注视频和导出，`src/security/qwen_budget.py` 管理跨进程额度及并发，`src/ui/qwen_view.py` 显示云端入口与结果。DeepSeek 评估新增 `vlm_eligible` 和 `vlm_reason`，只为可观察的视觉候选任务开放入口。云端结果单独标示来源和疑似状态，不生成或执行模型返回的代码。
