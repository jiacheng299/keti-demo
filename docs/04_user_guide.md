# Demo 用户使用手册

## 1. Demo 能做什么

本 Demo 在 Windows 笔记本上使用 CPU 处理本地视频。用户选择场景模板，或用 DeepSeek 把自然语言需求转成受白名单约束的 `SceneSpec`；系统再自动选择对应的本地小模型、跟踪器和规则，最终生成标注视频、事件、截图和结构化文件。

已接入的场景：

- 边防：人员进入禁区、车辆进入禁区、人员区域滞留。
- 火灾：火焰/烟雾目标检测，经连续帧规则从“疑似”升级为“确认”。当前固定素材只验证了火焰效果，不对烟雾效果作保证。
- 在岗：岗位区域缺员与回岗恢复。
- 打瞌睡：最多 5 张清晰人脸分别计时，判断持续闭眼与睁眼恢复。
- Qwen：对适合视觉判断而小模型无法完整执行的需求，提供手动抽帧检验入口。

当前不包含摄像头/RTSP、多路并发、本地大模型、身份识别、模型训练和生产部署。

## 2. 环境和必需文件

- Windows 10/11 x64。
- Python 3.13 64 位。
- 只使用 CPU，不需要 CUDA。
- 项目放在本机可写目录，无需使用开发者电脑的目录。
- 边防权重：`models/border/yolo11n.pt`。
- 火灾权重：`models/fire/fire_smoke_yolov8n.pt`。
- 人脸权重：`models/face/face_landmarker.task`。
- 建议验收视频：`assets/demo_videos/border_demo.avi` 和 `assets/demo_videos/fire_demo.avi`。

9 份示例视频已包含在 GitHub 中；安装器自动下载三套权重。运行结果和密钥不随仓库分发。

## 3. 首次安装

新电脑先安装 Python 3.13 x64，然后双击根目录 `setup.cmd`。或在项目根目录打开 PowerShell：

```powershell
py -3.13 scripts/setup_demo.py
```

验证依赖状态：

```powershell
.\.venv\Scripts\python.exe -m pip check
```

无需激活虚拟环境。详细要求及网络、DLL 等故障处理见 [新电脑安装运行指南](11_fresh_windows_setup.md)。

## 4. 配置 DeepSeek 和 Qwen（可选）

离线模板完成本地检测流程，不需要 API。本机网页“运行状态”分别提供“DeepSeek API 设置”和“Qwen API 设置”。输入 API Key 后点击“保存 / 修改 API Key”，会保存或替换该服务的密钥，不影响另一服务。密钥保存在本机操作系统凭据管理器，重启后仍可使用；已保存的密钥不会回填到输入框。点击对应的“清除已保存 Key”可删除该服务的凭据；留空保存不会删除旧密钥。Qwen 已接入云端抽帧检验，支持保存模型、地址、每日额度和公网开关，以及单独测试连接，详见 [Qwen 操作流程](09_qwen_video_inspection.md)。

分享模式不显示密钥编辑入口。请在本机访问 `http://127.0.0.1:8501` 设置，8502分享服务在刷新后读取相同凭据。本机页面启动命令为 `.\.venv\Scripts\python.exe -m streamlit run app.py --server.address=127.0.0.1 --server.port=8501`。

已保存密钥优先于环境变量：DeepSeek 使用 `DEEPSEEK_API_KEY`；Qwen 依次读取 `QWEN_API_KEY`、`DASHSCOPE_API_KEY`。清除保存的凭据不会删除启动环境变量，页面会显示当前来源。保存不验证账号、权限或额度。

保存不会调用接口。选择“DeepSeek 解析”并点击“生成场景配置”后，才会发送文字需求。已配置不代表鉴权已通过，请检查本次配置来源和错误提示。

也可以在启动 Streamlit 的同一个 PowerShell 窗口中设置环境变量作为备用：

```powershell
$env:DEEPSEEK_API_KEY="你自己的_API_Key"
```

只对当前终端会话生效。项目不会自动读取 `.env`，也不应将密钥写入代码、文档或 Git。清除当前终端中的密钥：

```powershell
Remove-Item Env:DEEPSEEK_API_KEY -ErrorAction SilentlyContinue
```

系统凭据优先于环境变量。网页清除按钮不修改启动环境中的密钥。系统凭据管理器不可用时会显示错误，不会改为明文文件保存。

## 5. 启动和停止

双击根目录 `start.cmd`，或在项目根目录使用 Streamlit 启动，不能直接运行 `python app.py`：

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py --server.address=127.0.0.1 --server.port=8501
```

终端出现 `Local URL: http://localhost:8501` 后，浏览器打开该地址。停止服务时，回到启动终端按 `Ctrl+C`。

## 6. 页面控件说明

### 6.1 运行状态

显示 DeepSeek API 是否已配置。这只影响“DeepSeek 解析”，不影响离线模板。模型只在分析期间加载，完成或失败后释放。

### 6.2 上传视频

支持 MP4、AVI、MOV、OGV 和 MKV，单文件不超过 500 MB。上传后显示分辨率、帧率、总帧数和时长。视频无法解码时会在模型加载前报错。

### 6.3 场景配置

`配置方式` 有两种：

- `离线模板`：只显示模板下拉框，不显示场景需求，不访问网络。
- `DeepSeek 解析`：只显示场景需求输入框，不显示模板下拉框。将需求解析为 JSON，随后仍由本地白名单校验；缺少 Key、请求失败或输出无效时，显示具体原因，不使用隐藏模板。可以重试或手动切换到离线模式。

`离线模板` 有五项：边防禁区、边防人员滞留、火灾检测、人员在岗监测、打瞌睡监测。“边防禁区”默认监测人员，可在配置卡片中追加或改选“车辆”；无需为不同目标分别选择禁区模板。应用只使用 `person`（人员）和 `car`（车辆）两个边防类别。模型检测到的小汽车、摩托车、客车、卡车在适配器中统一为 `car`，跟踪、规则判断、视频标注和新导出的事件均使用合并后的类别。`DeepSeek 解析` 模式下需填写 `场景需求`。点击 `生成场景配置` 后，必须先检查页面显示的需求理解、模型 ID、目标类别、规则和参数。

DeepSeek 会区分非场景需求、需求不明确、现有能力不支持和可以执行。例如“讲个笑话”被拒绝，“发现异常就报警”需说明异常类型，“检测未戴安全帽”会列出缺失能力，只有受支持的明确需求才生成本地配置。多个条件必须全部可执行，不能只保留其中一部分。不满足时旧配置会清除，不能开始本地分析；若全部条件适合从采样画面观察，页面显示“使用 Qwen 检验”，由用户手动启动云端分析。短信、身份识别、心理意图等不能直接交给视觉检验。程序同时校验输出结构、模型、规则、参数和需求映射，但自然语言理解仍可能出错，请核对页面摘要。详见 [操作流程](09_qwen_video_inspection.md)。

配置来源显示为“DeepSeek”或“离线模板”。切换模式、修改模板或需求会清除旧配置，必须重新点击“生成场景配置”。HTTP 401 表示密钥无效，402 表示余额不足，429 表示请求过于频繁；这些错误不会自动删除已保存的密钥。

生成后使用配置卡片修改监测目标、报警开关、冷却时间和规则阈值；模型按场景固定匹配，页面同时显示其检测置信度阈值。修改不需要再次请求 DeepSeek。修改完成后点击 **应用配置**，未应用或校验不通过时不能开始分析。原始 JSON 收起在“查看已应用配置 JSON”中。

**绘制边防禁区：**

1. 上传视频并生成一个边防配置，在“编辑规则”中选择需要修改的规则。
2. 选择进入禁区、离开禁区或区域滞留，填写区域名称；滞留规则另填秒数。
3. 用“选择绘图参考帧”找到容易看清地面的画面。
4. 矩形：点击“绘制矩形”，在画面按住并拖动，松开即完成。多边形：依次点击 3–20 个顶点，再点“完成多边形”。
5. 点击“拖动顶点”后可拖动白色圆点；可撤销一步或恢复已应用区域。交叉、重复顶点、面积太小或越界区域不能应用。
6. 如需多个区域，点击“添加区域规则”，再在“编辑规则”切换规则。各区域可使用不同触发条件，监测目标和报警冷却时间由整个场景共享。最多 20 条规则。
7. 点击“应用配置”后开始分析。黄色为当前编辑区域，灰色为其他区域。坐标保存为原视频像素，浏览器缩放不会改变区域位置；更换视频后应重新检查区域。

**火灾持续时间：**

确认阈值可选“秒”或“命中帧”。例如视频 25 FPS，填写 8 秒，程序计算 `ceil(8 × 25) + 1 = 201` 个命中帧，确保首次命中到确认达到 8 秒。DeepSeek 负责提取秒数，帧数由本地程序换算；换视频后会重新计算，需应用更改。严格连续检测将“允许连续漏检帧数”设为 0；容忍漏检时漏检帧不增加进度，确认可能延后。超过容忍值会清零。

### 6.4 开始分析

只有在“视频有效”且“已生成并应用有效场景配置”时按钮才可用。进度条显示已读取帧、已推理帧和已记录事件数。CPU 推理期间请不要刷新页面。页面暂无运行中停止按钮，因此建议使用 10–15 秒视频。

### 6.5 分析结果

页面显示读取帧数、推理帧数、检测数、事件数、模型和耗时；播放 H.264 结果视频；展示中文事件表和确认事件截图。播放器居中显示，最大宽度为 640 像素。

视频画面包含检测框、类别和 Track ID，不显示置信度。边防场景按配置中的 polygon 像素坐标绘制黄色禁区边界和淡色填充；同一区域的多条规则只绘制一次区域。事件发生时，相关目标框和禁区变为红色，顶部显示中文事件名称、目标/跟踪 ID、触发时刻，提示保留 3 秒视频时间。疑似火灾使用橙色提示，确认火灾使用红色提示并替换此前的疑似提示。多条事件最多同时显示三条，其余以数量提示，完整记录仍在事件表中。

提示保留时间仅影响视频展示，不改变规则阈值、冷却时间或事件数量。确认事件截图保留相同标注；没有中文字体的系统使用英文标签。修改展示代码后需重新分析视频以生成带新标注的结果。

视频底部最多显示三条规则进度：目标滞留时间、火灾确认进度和未报警原因。原因来自实际规则状态，包括首次观察、区域外、时长未达标、漏检清零、冷却中、报警关闭等。滞留沿用视频时间规则：同一目标 ID 暂时漏检后重现时会包含中间经过的时间；观察到其离开区域才清零，不能将其理解为每一帧均有检测证据。

展开“规则过程与未报警原因”，选择视频时刻，可查看当时所有规则和目标的完整状态。此滑块用于检查状态，不控制视频播放器。下载入口包括结果视频、事件 JSON、事件 CSV、运行摘要、场景配置及规则进度 JSONL。

## 7. 两个推荐流程

### 7.1 边防禁区

1. 上传 `assets/demo_videos/border_demo.avi`。
2. 选择 `离线模板` 和 `边防禁区`，默认监测人员；车辆场景可在生成配置后修改监测目标。
3. 点击 `生成场景配置`，确认模型为 `yolo_general`，检查或绘制区域并点击 `应用配置`。
4. 点击 `开始分析`。
5. 预期结果：画面出现人员检测框、类别和 ID，事件表出现“进入禁区”。

### 7.2 火灾连续帧确认

1. 上传 `assets/demo_videos/fire_demo.avi`。
2. 选择 `离线模板` 和 `火灾检测`。
3. 点击 `生成场景配置`，确认 `model_id` 为 `fire_smoke`。
4. 点击 `开始分析`。
5. 预期结果：事件表先出现“疑似火灾”，连续命中达标后出现“确认火灾”；确认事件有截图，疑似事件不保存截图。

## 8. 输出文件

每次分析写入独立目录 `runs/<时间>-<随机值>/`：

| 文件 | 内容 |
|---|---|
| `config.json` | 本次已校验的 SceneSpec |
| `events.json` | 完整事件字段，便于程序处理 |
| `events.csv` | 表格格式事件，UTF-8 BOM，可直接用 Excel 打开 |
| `summary.json` | 事件统计和运行指标 |
| `rule_progress.jsonl` | 每个推理帧的全部规则进度、目标 ID 和原因 |
| `snapshots/*.jpg` | 确认事件证据图 |
| `result.mp4` | H.264/yuv420p 标注视频 |

`runs/` 整个目录已被 Git 忽略。删除该目录会永久删除本地分析结果，需先备份有用文件。

## 9. 自动测试和重复验收

运行全部自动测试：

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

执行两个场景各 3 次的真实 CPU 验收：

```powershell
Remove-Item Env:DEEPSEEK_API_KEY -ErrorAction SilentlyContinue
.\.venv\Scripts\python.exe scripts\run_acceptance.py --repeat 3
```

通过时会输出 6 次运行结果、`acceptance_report.json` 以及每个场景的最后一份备用结果。验收器会检查必需文件、JSON/CSV/摘要事件数一致性、截图可读性、视频帧数和 H.264 标识。

## 10. 常见问题

### 直接运行 `app.py` 出现 `missing ScriptRunContext`

原因是启动方式错误。使用 `.\.venv\Scripts\python.exe -m streamlit run app.py`。

### 按钮不可用

先上传能够解码的视频，再点击 `生成场景配置`。两个条件都满足后 `开始分析` 才可用。

### 提示权重不存在

核对第 2 节的两个固定路径。权重名和 `config/models.yaml` 必须一致。

### DeepSeek 显示未配置或解析失败

在网页“DeepSeek API 设置”中保存 Key，或检查 Key 是否设置在启动 Streamlit 的同一终端中。不影响使用离线模板；网络/API 失败时页面显示原因，可手动切换到离线模式。

### CPU 分析太慢

使用已准备的 10–15 秒视频，关闭其他高负载程序，分析时不要重复点击或刷新。实测中边防 120 帧约 7.2–11.4 秒，火灾 275 帧约 14.0–14.8 秒；数值只代表当前电脑和固定视频。

### 浏览器不能播放结果

先确认页面已显示“分析完成”。系统在推理后还要做本地 H.264 转码。若转码报错，重启页面并重新分析；同时可从 `runs/backup/` 取用已验证的备用视频。

## 11. 已知限制和安全边界

- DeepSeek 只生成配置，不直接处理视频，其输出不会被当作代码执行。
- 小模型结果受素材、视角、光线和权重限制；演示结果不等于正式准确率、误报率或生产可用性证明。
- 火灾“疑似”是过程事件，因此无截图；“确认”事件保存截图。
- 边防事件需要 Track ID；火灾是画面级判断，Track ID 为空是正常行为。
- 页面没有运行中停止按钮；后端保留了停止契约，但本期 Web 未暴露。
- 不要将 API Key、私人视频或生成的 `runs/` 目录提交到 Git。

## 12. 人员在岗监测与打瞌睡监测

新增模板已接入离线模式和 DeepSeek 解析，可输入“岗位连续无人5秒后报警”或“分别监测画面中的多人，任意一人双眼持续闭合2秒后提示”。眼部模型最多处理 5 张人脸，使用一组共享阈值，分别计时。视觉推理都在本机 CPU 执行；DeepSeek 只接收文字和可选的视频尺寸、帧率，不接收视频画面。

### 人员在岗监测

1. 上传 `assets/demo_videos/on_duty_demo.mp4`。
2. 选择“离线模板 → 人员在岗监测”，点击“生成场景配置”。
3. 检查岗位区域，可切换参考帧看清人员工作位置，再绘制矩形或多边形。初始区域适配了办公室示例，新视频需要重新检查。
4. 默认最低 1 人、连续缺员 5 秒、回岗确认 1 秒、启动宽限 2 秒。区域按检测框中心统计人数，不区分员工身份。
5. 点击“应用配置 → 开始分析”。要监测多个岗位，使用“添加区域规则”，并为每个岗位分别绘图与设置人数。

绿色为在岗、黄色为缺员计时、红色为缺员报警、灰色为初始化。每次缺员只记录一次，回岗后可再次触发。
示例从开始即无人，因此在 2+5=7 秒报警；25.32 秒确认回岗。结尾缺员时间不足默认阈值，不强制产生第二次报警。

### 打瞌睡监测

1. 上传 `assets/demo_videos/drowsiness_demo.mp4`。
2. 选择“离线模板 → 打瞌睡监测”，点击“生成场景配置”。
3. 默认连续闭眼 2 秒报警，稳定睁眼 0.5 秒恢复。高级参数在“眼部阈值与画面质量”中；EAR 越小表示眼睛越接近闭合，睁眼阈值必须高于闭眼阈值。
4. 点击“应用配置 → 开始分析”。视频会画出人脸框、眼部关键点、双眼 EAR 和计时，并保存触发与恢复截图。

示例在 6.40 秒触发“疑似打瞌睡：持续闭眼”，9.65 秒恢复。`head_turn_control.mp4` 用于侧头对照，本机验证没有触发报警。
支持最多 5 张眼睛清晰的近景人脸，每张脸分别维护 ID、双眼 EAR、闭眼和恢复时间。丢脸、小脸或严重侧脸会中断该人的计时，不影响其他人；持续闭眼不能据此认定睡着。跟踪匹配不明确时分配新 ID 并重新计时。
当前不进行身份识别，也不保证在同位置无缝换人时辨别出不同人员。
多人测试可上传 `assets/demo_videos/multi_person_clear_1080p.mp4`（真实双人近景）或 `multi_face_staggered_composite.mp4`（同一演员的两路错时拼接）。详见 [多人眼部监测与测试](10_multi_face_drowsiness.md)。

首次在其他电脑安装时，运行根目录 `setup.cmd` 即可下载全部模型。已安装依赖后，也可单独运行：

```powershell
.\.venv\Scripts\python.exe scripts\download_models.py
```

两种新场景的事件 confidence 为空：它们是规则触发结果，不是模型输出的“缺员概率”或“睡着概率”。精确阈值见 `config.json`，计时原因及双眼测量见 `rule_progress.jsonl`。
